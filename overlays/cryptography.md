# Cryptography overlay

State notation, adversary model, security property and assumptions precisely.
Distinguish mathematical security, protocol design, implementation correctness and
operational deployment. Verify derivations and boundary conditions independently.

Prefer formal specifications, primary papers, recognised standards and reliable test
vectors. Treat nonce management, randomness, key lifecycle, side channels and misuse
resistance as implementation questions rather than consequences of an abstract proof.
Do not claim a primitive is secure without naming the relevant property and model.
